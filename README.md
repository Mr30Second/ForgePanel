# ForgePanel

Одно окно, с которого ставится и живёт Minecraft-сервер: ядро, моды и модпаки, запуск, консоль, копия мира. Windows 10/11, x64, интерфейс только тёмный и только по-русски.

## Скачать

**Releases → `ForgePanel-Setup.exe`** (≈72 МБ). Внутри уже лежат все файлы панели и .NET 8 — докачивать не нужно, прав администратора не запрашивается: программа ставится в `%LocalAppData%\Programs\ForgePanel`, появляется в «Установке и удалении программ» и в меню «Пуск». Удаляется вместе с собой, мир и сборки не трогает.

Мастер собран под .NET Framework 4.7.2 — он есть в Windows 10/11 из коробки.

## Что умеет

- **Сборки.** Библиотека: создание, дублирование, импорт/экспорт JSON, удаление с предпросмотром «было N, станет M» и выбором — снять только конфигурацию или стереть папку. Два вида: плитки с обложкой и компактный список на строку, плюс фильтр по избранному; отметка «в избранном» хранится в самом профиле и ездит вместе с экспортом JSON.
- **Ядра.** Vanilla, Paper, Folia, Leaf и Fabric панель качает сама (с докачкой и повторными попытками); Forge и NeoForge — запускают официальный установщик; Modrinth-модпак (`.mrpack`) приносит своё `server.jar`, и панель не ставит второе ядро поверх. Остальные (Quilt, Purpur, Bedrock Dedicated Server, Nukkit, PowerNukkit) показаны в списке честно: «ядро кладёшь сам», со ссылкой на источник.
- **Моды и датапаки.** Каталог Modrinth и CurseForge (моды, плагины, датапаки), установка выбранного мода в сборку, проверка обновлений модов по Modrinth. Для CurseForge нужен свой бесплатный API-ключ — вводишь один раз в «Настройках».
- **Модпаки.** `.mrpack` с Modrinth и обычный `.zip` с CurseForge (архив с `manifest.json` в корне) ставятся в новую сборку: файлы ровно по списку пака и по указанным номерам версий, контрольная сумма сверяется там, где пак её указывает (у CurseForge она приходит с API для каждого файла), папка `overrides`/`server-overrides` распаковывается. Пути вида `../` из архива наружу не выходят, `scripts/` из пака не запускается, а если отдельный файл CurseForge не отдал — установка не бросается на середине, пропущенные называются списком в конце.
- **Настройки сервера из панели.** MOTD, максимум игроков, online-mode, view-distance, сложность, allow-end (для Bukkit-семейства), RAM (`-Xmx`) и своя `java.exe` на каждую сборку, картинка для `server-icon.png`. Правки, сделанные руками в `server.properties`, панель не затирает.
- **Консоль.** Живой ввод/вывод сервера, история из `logs/latest.log`, перед остановкой — `save-all flush`, чтобы мир не остался недописанным.
- **Мир.** Копия перед запуском и откат на любую из них, сколько копий держать — настраиваемо; белые списки и операторы прямо в папке сборки.
- **Живёт само.** Автоперезапуск после падения и плановый перезапуск раз в сутки, графики RAM/CPU по окну процесса.
- **Разбор падений.** Вместо сырого стека — карточка с причиной («ядро собрано под более новую Java», нечитаемый конфиг и т. п.), плюс `crash.log` самой панели.
- **Друг не заходит.** Карточка «Как позвать друга» с проверкой CGNAT.
- **Окно.** Своя тёмная шапка вместо стандартного белого title bar, размер и положение окна запоминаются, диалоги — тоже свои, не `MessageBox`.

## Данные и секреты

Все пользовательские данные живут в `%LocalAppData%\ForgePanelV2` (сборки, `saves`, копии миров, `settings.json` с CurseForge-ключом). Ни установщик, ни деинсталлятор в эту папку не заглядывают, а в репозиторий она не попадает по `.gitignore` — ключ наружу не уезжает.

Конфиги сервера пишутся атомарно (`file.new` → перенос поверх старого + `.bak`), битый `servers.json` не затирается, а откладывается в `servers.json.broken-<дата>` и поднимается библиотека из `.bak`.

## Сборка из исходников

Нужны .NET 8 SDK и Visual Studio 2022+ (или Build Tools) с MSBuild.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\make-setup.ps1
```

Скрипт публикует панель (self-contained win-x64), собирает мастер на net472 и упаковывает payload внутрь одного файла — на выходе `dist\ForgePanel-Setup.exe` (отчёт в `dist\ForgePanel-Setup.exe.log`). Для возни с интерфейсом достаточно открыть `ForgePanel\ForgePanel.slnx` и нажать F5.

`.\scripts\publish-win-x64.ps1` — только публикация панели через `dotnet publish`, без мастера; готовый `ForgePanel.exe` запускается сам.

## Структура

| Папка | Что внутри |
| --- | --- |
| `ForgePanel/` | сама панель: WPF на .NET 8, интерфейс целиком в code-behind (XAML — только `App` и `MainWindow`) |
| `ForgePanel.Setup/` | мастер установки и он же деинсталлятор: `net472`, pure-code WPF, без XAML |
| `scripts/` | сборочные PowerShell-скрипты |
| `build-check.bat` | сборка проекта через MSBuild с отчётом в `build.log` |

Формат установщика: `[мастер][zip с payload][16-байтный футер]`. Футер нужен потому, что `ZipArchive` из .NET Framework читает смещения центрального каталога как абсолютные и на «exe сверху» падает; в коде это `SliceStream`.

## Чего здесь сознательно нет

Веб-панели, Docker, RCON и отцепленного запуска сервера, светлой темы, английской локализации, Purpur-ядра (его API не отдаёт корректный Range-ответ).
